# TabPals — Approved Plan

1. People & events: global people directory; each event selects members from it. Import members from a previous event via a checklist with select all / select none (covers all, all-except, multi-select). Saved groups (e.g. a family) can be added in one tap. Duplicate person/group names are blocked using Persian normalization.
2. Vouchers: each expense is an accounting voucher with a sequential number per event. Record time (Jalali date, weekday, time) is automatic and immutable; expense date is a separate editable field. Voucher types: expense, contribution to treasurer, settlement payment. An expense may have multiple payers with amounts. Events are open or closed. Closed by end date or manually; closed events block new vouchers; reopening requires a reason and is logged.
3. Audit trail: no voucher is ever deleted. Every edit creates a new revision storing field-level before/after, time and device. Deletion = void with reason.
4. Expense entry flow: big + button. Amount → payer (default = last payer) → description (typed or voice) → "Is everyone's share equal?" Yes = save. No = untick non-participants → "Equal among the rest?" No = set shares per person by weight, percent, or exact amount → show summary and confirm before save. Share_i = amount × w_i / Σw; distribute rounding remainder deterministically so shares always sum exactly to the amount. Calculation engine fully unit-tested.
5. Attachments: photo/video from camera or gallery (images compressed client-side, video capped ~30s), in-app audio recording and audio file upload. Speech-to-text: web = Web Speech API (fa-IR) when online; offline = audio saved and flagged "pending transcription", convertible later with one tap; native Android = system speech recognizer. Keyboard dictation also works in text fields.
6. Multi-user aggregation: all records have global ULIDs; every change is stored as an operation (who, when, device, what). Event creator shares an "invite package" (.tabpal file) so everyone has the same event and member IDs. Users exchange "sync packages" (.tabpal files via WhatsApp/Telegram/share sheet); import merges by ID, deduplicates, and flags conflicting concurrent edits for manual choice, never silently losing data. Optional "ledger keeper" mode. Same operation log will later power online sync.
7. Dashboard: updates instantly after each voucher. Per member: paid, share, balance (debtor/creditor). Event totals. Suggested settlement with minimum number of transfers. One-tap export of the summary as an image ready for WhatsApp. Per-member account statements: available ONLY for closed events (closed manually or by end date). Generated per member, stored inside the event with number, issue date and version history; marked outdated if the event is reopened after issue. Output as image (WhatsApp-friendly) and PDF. Send menu: (1) image/PDF via the system share sheet (WhatsApp, Telegram, Rubika, Bale or any installed app); (2) text summary directly to WhatsApp (to the member's phone if set) or Telegram; (3) SMS with a short summary and a link opening the full statement on the app site, statement data encoded in the URL fragment (no server). Bulk: select several or all members; to one chat = all images shared at once; to each member individually = a send queue with per-member send buttons and sent markers.
8. Backup: zip with selectable components (data only / + images / + audio / + video; all or selected events). Last 5 backups kept in rotation (oldest replaced). Web: stored inside the app, shareable via share sheet; desktop Chromium may also write to a user-chosen folder. Native Android: written to a user-visible device folder with the same 5-file rotation. Restore: replace or merge. Optional password encryption (AES-GCM).
9. Online readiness: layered architecture, repository interfaces with a local Dexie adapter only; sync-ready fields on all records; ONLINE_ENABLED=false. Server choice deferred (must be reachable from Iran).
10. App name defined in one config constant.
11. Native packaging & updates: Capacitor wraps the same web build. Android: GitHub Actions builds a signed release APK (keystore in GitHub Secrets, same key forever), publishes it to GitHub Releases; versionCode derived from package.json version so each APK installs over the previous one keeping data. In-app update check (when online) reads version.json and shows a download link. iOS: Capacitor iOS project generated and kept ready; distribution deferred (requires an Apple Developer account); PWA remains the iPhone install path. PWA and HTML deployment remain unchanged. Native Android: direct send buttons with file attachment for WhatsApp, Telegram, Rubika and Bale.

Theme: system / light / dark, user-selectable. A dedicated visual design stage (2.5) follows Stage 2: cream/olive/gold palette, reversible via a git tag and isolated PR.

Stages: 0 foundation, 1 people & events, 2 vouchers & calculation engine, 3 dashboard & settlement, 4 audit trail, 5 attachments & voice, 6 backup, 7 multi-user sync, 8 dormant online layer, 9 native Android APK & iOS project.
